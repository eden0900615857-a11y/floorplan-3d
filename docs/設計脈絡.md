# 房屋內部裝修模擬系統：設計脈絡

最後更新：2026-09-30　｜　狀態：第六階段完成，可以擺家具、換地板與牆面顏色

---

## 1. 一句話說明
使用者上傳房屋平面圖，網頁自動產生 3D 模型，接著可以在 3D 裡擺家具、換地板與牆面材質，模擬裝修後的樣子。

## 2. 目標使用者（已決定：一般屋主）
- **屋主／買房族**：想看新家格局、試不同裝潢風格。
- **室內設計師**：快速把客戶的平面圖變成 3D，跟客戶溝通提案。
- **房仲**：把物件平面圖變成可以瀏覽的 3D 給買方看。

不同對象需要的精準度與功能差很多，所以這一題要最先決定。

## 3. 功能範圍

### 第一版（MVP）一定要有
1. 上傳平面圖（JPG / PNG，之後再支援 PDF）。
2. 自動辨識牆，產生 3D 牆體。
3. **2D 校正畫面**：自動辨識一定會有錯，使用者可以拖曳修正牆、刪除多餘的線、補上漏掉的牆。
4. 設定比例尺：點圖上兩點並輸入實際長度（例如 3.5 公尺）。
5. 3D 瀏覽：鳥瞰旋轉、縮放。
6. 存檔、重新開啟專案。

### 第二版
- 自動辨識門、窗，在牆上挖出門窗洞。
- 辨識房間與房名（客廳、臥室…），計算每間坪數。
- 第一人稱室內漫遊。

### 第三版：裝修模擬
- 家具庫：拖曳擺放、旋轉、調整尺寸。
- 更換地板、牆面、天花板材質與顏色。
- 多個裝修方案並排比較。
- 匯出圖片、分享連結、匯出 3D 檔（glTF）。
- 進階：估價清單（依材質面積算材料量）。

### 先不做
- 多樓層、樓梯（除非 Q4 決定要）。
- 結構／水電圖面。
- 手機上的完整編輯（手機先只做瀏覽）。

## 4. 使用流程
```
上傳平面圖
  → 系統自動辨識（牆 → 門窗 → 房間）
  → 2D 校正：確認比例尺、修正牆與門窗
  → 產生 3D 模型
  → 裝修模擬：擺家具、換材質
  → 存檔／分享／匯出
```
關鍵設計：**自動辨識 + 人工校正** 兩段式。不追求 100% 自動，而是讓修正很快。

## 5. 辨識方式比較

| 做法 | 優點 | 缺點 |
|---|---|---|
| A. 傳統影像處理（OpenCV）| 免費、快、可離線、雛形已驗證可行 | 只擅長牆；門窗、房名要另外處理；圖面風格差異大時需調參數 |
| B. 自訓練 AI 模型（分割／物件偵測，公開資料集 CubiCasa5k）| 門窗房間一次辨識、準確度高 | 需要 GPU、訓練與標註成本，台灣圖面風格可能要補資料 |
| C. 多模態 AI API（上傳圖片讓 AI 讀出 JSON）| 開發最快、能讀房名與尺寸文字 | 每次呼叫要費用、座標精準度不穩，需搭配 A 修正 |

**建議**：A 負責牆的精確位置，C 負責讀房名、尺寸標註、門窗大略位置，兩者合併後交給使用者校正。等累積足夠使用者校正過的資料，再考慮 B。

## 6. 系統架構
```
[瀏覽器]
  React 介面
  ├─ 2D 校正編輯器（Canvas / SVG）
  └─ 3D 場景（Three.js / React Three Fiber）
        ↑ 平面圖 JSON
[後端 API]  Python FastAPI
  ├─ 影像處理（OpenCV）
  ├─ AI 辨識（API 或自有模型）
  └─ 專案存取
[儲存]
  資料庫（PostgreSQL 或 Supabase）＋ 檔案儲存（原始圖、家具模型、材質貼圖）
```
- 前端只認「平面圖 JSON」，辨識方法日後怎麼換都不影響 3D 與裝修功能。
- 第一版也可以不做後端：辨識在瀏覽器裡跑（雛形就是這樣），存檔先存在使用者電腦。等要帳號、分享、AI 辨識時再加後端。

## 7. 平面圖 JSON（核心資料格式）
整個系統都圍繞這份資料。單位一律公尺，座標原點在平面圖左上角。

```json
{
  "version": 1,
  "unit": "m",
  "source": { "image": "plan.jpg", "pxPerMeter": 66.2 },
  "walls": [
    { "id": "w1", "a": [0, 0], "b": [12, 0], "thickness": 0.2, "height": 2.8 }
  ],
  "openings": [
    { "id": "d1", "type": "door", "wall": "w1", "offset": 5.3, "width": 0.9, "height": 2.1, "swing": "left" },
    { "id": "n1", "type": "window", "wall": "w1", "offset": 1.2, "width": 1.5, "height": 1.2, "sill": 0.9 }
  ],
  "rooms": [
    { "id": "r1", "name": "客廳", "polygon": [[0,4],[8.5,4],[8.5,7.9],[0,7.9]], "floor": "oak-light" }
  ],
  "furniture": [
    { "id": "f1", "model": "sofa3", "pos": [3.2, 6.8], "rotation": 180, "w": 2.1, "d": 0.9 }
  ],
  "materials": { "wall": "paint-white", "ceiling": "paint-white" }
}
```
重點：
- 牆存成「中心線 + 厚度」，不是像素。門窗掛在某面牆上：`offset` 是開口中心到牆 `a` 端的距離，移動牆時門窗會跟著走。門的 `hinge` 是門軸靠近牆的 `a` 或 `b` 端，`swing` 是往 a→b 方向的左側或右側開（以螢幕上看到的方向為準）。
- 房間的 `floor` 是地板材質 id（`js/materials.js`：oak-light、oak-dark、tile-white、tile-grey、cement、marble），沒填就用淺色木地板。
- 家具的 `model` 是家具庫的 id（`js/furniture.js`），`pos` 是中心點，`rotation` 是順時針角度（0 度正面朝下），`w`、`d` 是寬和深（公尺）。比例尺縮放時家具只移動位置、不改尺寸。
- `materials.wall` 是牆面顏色 id（paint-white、paint-warm、paint-greige、paint-sage、paint-blue、paint-charcoal）。
- 裝修方案 = 同一份平面圖 + 不同的 `furniture` 與材質設定。

## 9. 已決定事項（2026-09-26）
| 題目 | 決定 |
|---|---|
| 主要使用者 | 一般屋主 |
| 支援的圖面 | 先做黑白施工平面圖（CAD 輸出），再支援建商彩色格局圖 |
| 辨識方式 | 先用影像處理（OpenCV 類做法），不用 AI |
| 多樓層 | 先不做，一次一層 |
| 帳號與雲端存檔 | 第一版不做，存在使用者電腦 |
| 家具模型 | 免費開放模型；完整後再考慮串接真實家具品牌 |
| 裝置 | 電腦編輯，手機或電腦瀏覽 |
| 專案性質 | 個人專案 |
| 程式碼 | 新建 GitHub repo |

因為是個人專案、辨識只用影像處理、不需帳號，**第一版可以做成純前端網頁**（辨識在瀏覽器裡跑），不需要後端伺服器，可以免費部署在 GitHub Pages。

### 兩種圖面的比較
- **黑白施工圖**：比較簡單也比較精確。線條乾淨、牆的厚度一致、通常有尺寸標註可以換算比例尺。雜訊主要是尺寸線、軸線和文字，都比牆細，可以用「最小牆厚」濾掉。
- **建商彩色格局圖**：比較難。地板有木紋或磁磚圖案、家具是彩色插圖、有陰影和浮水印，常常沒有標尺寸，而且為了美觀比例不一定準。需要多做一步顏色處理，把「深色、低飽和度」的牆從彩色背景中分出來。
- 一般屋主手上最常有的其實是彩色格局圖，所以它是第二步一定要做的。

## 10. 已知的技術風險
- 圖面風格差異極大，辨識準確度是最大風險，所以校正編輯器是必要功能，不是加分項目。
- 比例尺：有些圖沒有標尺寸，只能靠使用者設定。
- 3D 效能：家具多時手機會卡，需要簡化模型與材質。
- 著作權：使用者上傳的建商圖面，儲存與分享需注意。

## 11. 真實施工圖測試（2026-09-30）
用 Eden 提供的二次施工圖 PDF（A1 圖紙，一張有一樓、二樓、屋頂突出物三張平面圖，加上面積表與圖框，比例 1/100、單位公分）測試：
- 第四階段的圖片辨識幾乎完全失敗：只找到零碎的牆、0 個房間。原因是真實施工圖的**牆是兩條細線畫成的空心牆**，不是範例圖那種塗黑的粗線；圖上還有地界線、退縮線、尺寸線、家具線等大量雜線。
- 這份 PDF 是 CAD 直接輸出的向量圖（約 54 萬段線），也保留了 CAD 圖層，但牆大多不在叫 WALL 的圖層上，所以**不依賴圖層名稱**，改用幾何規則：成對平行線是牆、四分之一圓是門、牆裡的平行細線是窗、小矩形是柱子。
- 結果：一樓找出 4 個空間（客餐廳與廚房、工作室等因為開放通道相連算成一間）、6 扇門、10 扇窗；二樓找出 9 個空間、6 扇門。家具、廚具的平行線偶爾會被當成牆，仍需要 2D 校正。
- 下一步的風險：只用一份施工圖調整過規則。不同事務所的畫法（牆內填斜線、牆畫成實心、門弧畫成折線）可能需要再調整，需要更多真實圖面測試。
- 拍照或掃描的施工圖沒有向量線條，仍然走圖片辨識，也還不支援空心牆，之後可以沿用「成對平行線」的做法。
